# codex-opero v0.2.11

## 한국어

앱을 업데이트한 뒤 Antigravity의 `gemini` 키체인 접근 요청이 `항상 허용`을 눌러도 다시 표시되던 문제를 수정하고, 업데이트 안내 문구를 다듬었습니다.

### 변경 사항

- **Antigravity 키체인 접근 방식 변경**: agy 로그인(`gemini`)과 갱신 토큰 캐시(`codex-opero.AntigravityOAuth`)를 Claude와 같이 `/usr/bin/security`로 읽고 갱신합니다. 앱의 ad-hoc 서명은 빌드마다 바뀌므로 키체인 API로 직접 접근하면 업데이트할 때마다 승인을 다시 요청했습니다. 이제 앱이 키체인 API를 사용하지 않아 업데이트 후에도 승인 요청이 반복되지 않습니다.
- **캐시 실패 시 계속 조회**: 갱신 토큰 캐시를 읽을 수 없으면 조회를 중단하지 않고 agy 원본 로그인으로 진행합니다.
- **업데이트 안내 문구 정리**: 버전과 파일 이름 뒤에 붙던 `이(가)`, `을(를)`을 없애고 자연스러운 문장으로 바꿨습니다.

### 검증

- 전체 91개 테스트가 통과했으며 v0.2.11(build 29) DMG 생성, 서명·체크섬 검증을 완료했습니다.
- 실제 `gemini` 항목과 갱신 토큰 캐시를 새 방식으로 읽는 것을 확인했고, 임시 키체인 항목으로 생성·갱신을 검증했습니다.
- v0.2.10의 앱 내 업데이트로 이 버전을 설치하는 과정과 이후 업데이트에서 승인 요청이 사라지는지는 실제 사용으로 확인이 필요합니다.

v0.2.10 이하에서 만든 갱신 토큰 캐시는 이전 앱 빌드에만 접근이 허용되어 있어, 처음 한 번 `security`의 접근 허용 요청이 표시될 수 있습니다. 이전 빌드가 남긴 `codex-opero` 접근 권한은 자동으로 제거되지 않습니다.

## English

Fix Antigravity's `gemini` Keychain access prompt reappearing after app updates even after choosing `Always Allow`, and polish the update alert wording.

### Changes

- **Change Antigravity Keychain access**: Read and update the agy login (`gemini`) and the refreshed-token cache (`codex-opero.AntigravityOAuth`) through `/usr/bin/security`, as with Claude. The app's ad-hoc signature changes with every build, so direct Keychain API access required approval again after each update. The app no longer uses the Keychain API, so prompts no longer repeat after updates.
- **Continue when the cache fails**: When the refreshed-token cache cannot be read, continue with the original agy login instead of failing the request.
- **Polish update alert wording**: Rephrase Korean alerts to avoid placeholder particles after version numbers and file names.

### Validation

- All 91 tests passed. The v0.2.11 (build 29) DMG was generated and its signature and checksum verified.
- Verified reading the live `gemini` item and refreshed-token cache through the new path, and creating and updating a temporary Keychain item.
- Installing this version through the v0.2.10 in-app updater, and whether prompts stop on later updates, require real-world use to confirm.

Refreshed-token caches created by v0.2.10 and earlier grant access only to earlier app builds, so `security` may ask for access once. `codex-opero` access entries left by earlier builds are not removed automatically.
